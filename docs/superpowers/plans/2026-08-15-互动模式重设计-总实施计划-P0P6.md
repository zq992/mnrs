# ⛔ 前置门槛（必须先解决，否则其他代码无法实施）

以下问题来自四轮三引擎审核发现的口径冲突与架构债，**必须先解决，才能实施 P1 之后的代码**（不解决会导致连锁状态不一致）：

| # | 前置问题 | 原因 | 解决位置 |
|---|---|---|---|
| 1 | 年制时间：季→年（`advance_year()` + `AnnualSettlement`，推进与结算解耦） | 出行/行动点/晋升/战争全用"年"口径，不解决全线卡死 | P0-3 |
| 2 | `ADULT_AGE=16` 统一常量 | 代码里 16 岁成人礼与 20 岁"弱冠"里程碑冲突，会触发两次成年 | P1-2 |
| 3 | 关闭诸侯→天子晋升（删 Lv5→6 分支） | `can_promote` 仍允许诸侯升天子，与"天子不可达"冲突 | P2-3 |
| 4 | 统一国家注册表 `StateRegistry` | `FEUDAL_STATES` 静态数组 vs dynasty JSON 双数据源，受封/地图/出行会互相矛盾 | P0-4 |
| 5 | 统一行动入口 `ActionService.execute()` | 行动点可被快捷键/弹窗/自动模式多入口绕过 | P0-2 |
| 6 | 剧本协议 `ScenarioDefinition` schema 校验 | JSON 拼写错误运行期才暴露，缺校验则"加数据不改代码"不成立 | P0-4 |
| 7 | 出行状态机 `TravelState` + `MapGraph`（图拓扑） | 不可瞬移的前提；现 `change_location()` 任意跳 | P4-1 |
| 8 | 战争纯结算器 `WarResolver.resolve()` | 现 `_calculate_power()` 是个人影响力，误作国家军力会算错胜负 | P5-1 |
| 9 | 独立时代 ID `current_era_id` | 现只有 `current_dynasty_id`，时代切换无法驱动事件池/国家/地图归属 | P4-2 |

> 这 9 项是"硬门槛"，对应 P0 架构地基 + 各阶段的第一个任务。解决前不碰任何玩法内容。
