# 华夏模拟人生（西周篇）· 对标优化需求框架书

> 文档编号：03 ｜ 版本：v1.0 ｜ 日期：2026-08-15 ｜ 状态：定稿
> 主题：评估 mnrs 现有架构能否参考《大周列国志》《无悔华夏》《古代人生》《现代人生》四款模拟历史/人生游戏进行优化，并给出优化后的需求框架。
> 定位：本文为**支撑文档**——第四章架构分层（AR 系列）被 01 §八 引用为架构地基依据；四游戏对标分析已消化进 01（界面分层）/04（跨平台选型），本文保留原始分析供追溯。
> 依据：`scripts/`（约 1.2 万行 GDScript 已核实）、`02_系统需求.md`（8 大系统）、`docs/superpowers/specs/2026-08-15-玩法重设计-design.md`（P1-P4 计划）。
> 约束：中文注释；无后世词；不新增美术资源；旧档 `.get()` 兜底；本框架书只定"要什么/为什么"，不写"怎么实现"的代码级细节（实现交实施计划）。

## 〇、结论先行

**能否借鉴？——能，且正是当前架构最需要的一步。**

mnrs 与这四款游戏本质是同一个品类（"人生模拟 + 历史经营"），玩法方向高度重叠：世代传承、时间推进、身份阶层、事件抉择、经济循环——这些 mnrs 已经都有或已在需求文档规划。真正的差距不在"缺玩法"，而在**架构承载能力**：当前代码把"UI 渲染、业务动作、数值结算、冷却管理"全塞进两个巨型单文件（`hud.gd` 5531 行、`character_manager.gd` 2882 行），数据全用无 schema 的 Dictionary，导致每加一个系统（田地/装备/官职）都往同一个文件里堆代码、越堆越难改。

四款游戏能教 mnrs 的，按优先级从高到低：

| 优先级 | 借鉴来源 | 借鉴内容 | 解决 mnrs 什么问题 |
|---|---|---|---|
| P0 | 四款共有 | **分层解耦 + 数据模型化**（UI/系统/模型/数据分离） | 上帝类、数据无 schema 的根本问题 |
| P0 | 大周列国志 | **个人层 + 国家层双层模拟** | "升到诸侯就无事可做"的老问题（design.md 已点名） |
| P1 | 无悔华夏 | **剧本化历史进程 + 政策/科技树** | 现有 P4 历史事件只有 6 个点，缺"线"和"树" |
| P1 | 古代人生 | **人生阶段线细化**（出生→幼年→少年→成年→中年→老年） | 当前只有"成人礼"一刀切，成长过程空白 |
| P2 | 现代人生 | **目标导向的财富闭环** | 现有经济循环只算"进多少出多少"，缺"攒钱为什么" |
| P2 | 无悔华夏 | **放置式推进 + 决策点** | 自动推进无暂停、无节奏（design.md 已列可选） |

**一句话结论**：mnrs 不需要推翻重来，需要的是把"散在两个上帝类里的业务"重构为"分层 + 系统化"，并在其上补三块玩法（诸侯国家经营、剧本化历史线、人生阶段线），就足以对标四款游戏的完整度。

### 1.3 架构问题（本框架书要解决的根因）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| A1 | **上帝类** | `hud.gd` 5531 行、`character_manager.gd` 2882 行，UI 与业务不分 | 加一个系统就要在 5000 行文件里找插入点，回归风险高 |
| A2 | **数据即字典，无 schema** | `current_character`/`family_data`/`household_data` 全是 `Dictionary` | 无类型检查、字段拼错静默为 null、全靠 `.get()` 兜底防崩 |
| A3 | **业务逻辑下沉在 UI 层** | 大量 `_do_farming`/`_on_socialize`/`_on_attend_court` 写在 `hud.gd` | 无法复用（如事件系统要触发"耕作"得调 UI 函数）、难以单测 |
| A4 | **冷却系统分散、易刷** | `_can_act`/`_mark_acted` 内存变量不进存档，部分动作不查冷却 | design.md 已列"家族无限刷"必修项 |
| A5 | **单例 + 直接改状态，无命令/溯源** | 状态变更直接 `dict[key]=v`，无统一入口 | 难做回放、难做"抉择后悔"、难定位数值异常 |

> 这五个问题正是四款游戏在架构层面共同避免的——它们都采用"数据模型 + 系统服务 + UI 薄壳"的分层。A1-A5 是本次优化的一号工程。

## 二、四款对标游戏拆解

> 说明：以下"核心玩法"为该游戏公开可见的玩法特征，用于提炼**架构模式**（不是照抄内容）；"可借鉴模式"是我对 mnrs 的落地建议。每款游戏只提炼 2-3 个真正可用的模式，避免贪多。

### 2.1 《大周列国志》—— 国家经营 + 双层模拟

- **核心玩法**：玩家扮演诸侯君主，经营封国。四支柱：内政（人才委任/赋税/建设）、外交（结盟/联姻/征伐）、军事（练兵/出征）、人才（招募武将文臣培养）。
- **可借鉴模式 ①：个人层 / 国家层双层模拟**
  - mnrs 现状：玩家身份到"诸侯"（social_level 5）后就断了，design.md 明确"升到诸侯就无事可做"。
  - 落地：当角色晋诸侯后，切换进入"封国经营"层——角色仍是本人（个人层继续），但新增"国家层"（封国）数据与操作：内政（筑城/劝农/举才）、军政（练兵/出征）、外交（会盟/联姻/纳贡）。个人层的声望/势力/财富对国家层产出加权，国家层政绩反哺个人层爵位晋升。
- **可借鉴模式 ②：人才系统（招募-培养-委任）**
  - mnrs 现状：门客只有"忠诚/献策"（社会系统 5.2.3），是附属。
  - 落地：把门客升级为"可委任"的人才——门客有技能/忠诚，可委任为封国的"邑宰/司马/司寇"等职，委任后其技能影响该国对应系统的产出。让"养门客"有目的（不是为了养而养）。

### 2.2 《无悔华夏》—— 剧本化历史进程 + 政策树

- **核心玩法**：部落/文明从无到有经营，历史剧本推进，名臣名将卡牌养成，政策/科技树逐层解锁，放置挂机 + 关键决策点（轻操作、重决策）。
- **可借鉴模式 ①：剧本化历史进程（时间轴事件线）**
  - mnrs 现状：design.md 已规划 P4"历史事件之门"6 个点（三监之乱→幽王亡国），但只是孤立的事件点。
  - 落地：把 6 个孤立事件点扩展为**贯穿整个西周的剧本时间轴**——每个事件不是"触发一次就完"，而是沿时间轴串成一条"朝代剧情线"，事件之间有前后因果（三监之乱→周公还政→成康之治→昭王南征→厉王→幽王）。玩家每代在轴上的 1-2 个窗口做抉择，抉择结果写入"家族命运线"，影响下一代开局。
- **可借鉴模式 ②：政策/科技树（逐层解锁）**
  - mnrs 现状：无。
  - 落地：新增"国策/礼法树"——分 内政/军备/礼乐/农商 四条线，每条 3-4 层，用"政绩/声望/资源"解锁，解锁给封国经营加成或解锁新动作。给中后期玩家一个"往哪发展"的长期目标（对标现代人生的"多线程人生目标"）。

### 2.3 《古代人生》—— 人生阶段线 + 世代传承

- **核心玩法**：从婴儿出生经历成长、读书科举、婚姻、生子，直到死亡传承下一代，文字抉择 + 属性养成 + 随机事件池。
- **可借鉴模式 ①：人生阶段线细化**
  - mnrs 现状：角色 0 岁出生 → 16 岁成人礼（一次性选职业）→ 此后一路成年，成长过程几乎空白；中间只有"教育分配职业"一笔带过。
  - 落地：把一生拆成**阶段**，每阶段有专属动作与属性变化节奏：
    - 幼年（0-6）：被动成长，父母教育投入影响初始属性
    - 少年（7-15）：读书习武（选学六艺，决定成年职业方向）＋ 少年事件（拜师/游学）
    - 青年（16-30）：立业（职业/婚配/生育），当前玩法主体
    - 中年（31-50）：经营（官职/封国/门客），当前"晋升"主体
    - 老年（51+）：传承（培养继承人/立嗣/交代后事），死亡触发世代传承
  - 这是"人生模拟"品类的灵魂，mnrs 缺了它，所以玩起来像"刷数值"不像"过一生"。
- **可借鉴模式 ②：随机事件池（按人生阶段分层）**
  - mnrs 现状：event_manager + events.json 已有事件机制，但事件未按人生阶段/身份分层。
  - 落地：事件池按"阶段 × 身份 × 国别"三层过滤，幼年只出成长事件、诸侯只出国政事件，避免"庶人触发王命事件"的出戏。

### 2.4 《现代人生》—— 生活经营 + 财富闭环

- **核心玩法**：现代背景，工作/房产/婚姻/子女/投资多线程经营，时间按月推进，财富是核心资源，一切围绕"攒钱达成人生目标"。
- **可借鉴模式 ①：目标导向的财富闭环**
  - mnrs 现状：02_系统需求.md 已设计"经济循环（田/官/外快三通道 + 开销封顶）"，但只解决"收支平衡"，没回答"攒钱干什么"。
  - 落地：给财富绑"目标"——购田、扩建仓库、置办装备、嫁女聘礼、扩建封国、上下打点（谋官/受封），让"赚钱"有明确去向，形成"生产→积累→投入→更大生产"的正向循环，而不是数字越堆越大。
- **可借鉴模式 ②：多线程人生目标**
  - mnrs 现状：玩家没有"目标清单"，玩到哪算哪。
  - 落地：新增"人生目标"轻系统——开局按出身给 3-5 个可选目标（如"位至卿大夫"/"受封建侯"/"家财万贯"/"门客三千"），达成给成就/结局评价，未达成在死亡时结算"这一生"的评级。给玩家"这一代我要干嘛"的牵引。

## 三、借鉴可行性对照（现状 vs 目标）

| 借鉴模式 | 来源 | 可行性 | 依赖前置 | 与现有计划关系 |
|---|---|---|---|---|
| 分层解耦 + 数据模型化 | 四款共有 | ✅ 高（纯重构，不新增玩法） | 无 | 应在 P1 之前/并行做（重构先行） |
| 个人层/国家层双层模拟 | 大周列国志 | ✅ 高（复用现有封地/家兵/官职） | 数据模型化（A2） | design.md P3 之后新增"P5 诸侯经营" |

| 剧本化历史时间轴 | 无悔华夏 | ✅ 高（复用 event_manager） | design.md P4 事件机制扩展 | P4 扩展为"时间轴"而非"孤立点" |

| 人生阶段线 | 古代人生 | 🔵 中（改动大，触及开局/成人礼/死亡全流程） | 数据模型化（A2） | 新增 P6，与现有"成人礼"打通 |
| 阶段分层事件池 | 古代人生 | ✅ 高（复用 events.json，加过滤字段） | 无 | P4/P6 附带 |
| 目标导向财富闭环 | 现代人生 | ✅ 高（复用经济循环） | 02_系统需求 P6-1 | 经济循环的"目标层"补充 |

**可行性总判断**：九个借鉴点里 6 个高可行、2 个中可行、1 个暂缓。核心阻力不是玩法设计，而是 A1-A5 的架构债——不先分层，任何一个新模式都会继续堆进 `hud.gd`，债务复利。

## 四、优化后的目标架构愿景

### 4.1 四层架构（对标四款游戏的共同分层）

```
┌─────────────────────────────────────────────────────────┐
│ 表现层 Presentation（薄壳，只做渲染与交互）                │
│   hud.gd / event_dialog / character_create / 各面板       │
│   —— 只发"命令"，不做业务逻辑，不直接改数据              │
└───────────────────────────┬─────────────────────────────┘
                            │ 信号 + 命令（Command）
┌───────────────────────────▼─────────────────────────────┐
│ 应用层 Application（系统服务 Manager，单一职责）            │
│   TimeSystem    时间/季节/推进/暂停                        │
│   LifeSystem    人生阶段/成长/死亡/传承                    │
│   StateSystem   国家经营（诸侯）/政策树                    │
│   EconomySystem 田/仓/俸禄/外快/装备 结算                 │
│   CareerSystem  职业/官职                                  │
│   SocialSystem  门客/社交/声望/家规                        │
│   EventSystem   事件触发/前置/效果/剧本时间轴              │
│   WarSystem     征战/军功/家兵                            │
└───────────────────────────┬─────────────────────────────┘
                            │ 领域模型（Resource）
┌───────────────────────────▼─────────────────────────────┐
│ 领域层 Domain（数据模型，类型化 + 信号 + 可序列化）         │
│   Character / Family / Household / Land / Granary         │
│   Faction(封国) / Talent(门客) / Timeline(剧本轴)         │
│   —— 用 Godot Resource/class_name，替代裸 Dictionary      │
└───────────────────────────┬─────────────────────────────┘
                            │ 数据
┌───────────────────────────▼─────────────────────────────┐
│ 基础设施 Infrastructure                                   │
│   存档(SaveGame) / JSON 资源 / 数值配置表 / 事件池        │
└─────────────────────────────────────────────────────────┘
```

**关键设计（架构层面的"借鉴落地"）**：

1. **命令模式**：UI 按钮 → 发 `DoFarmingCommand` 这类命令给应用层 → 应用层执行并改模型 → 模型发信号 → UI 刷新。状态变更只有一个入口（应用层），解决 A3/A5（业务下沉、无溯源），也为"抉择后悔/回放"铺路。
2. **Resource 模型化**：`Character`/`Family` 等从 Dictionary 升级为 `class_name` Resource，字段有类型、有默认值、可发 `changed` 信号，解决 A2（无 schema）。存档序列化用 Godot 原生 Resource 序列化，旧档通过一次迁移把 Dictionary 灌入 Resource（`get()` 兜底逻辑保留在迁移层）。
3. **系统化 Manager 拆分**：`hud.gd` 里的 `_do_farming`/`_on_socialize`/`_on_attend_court` 等业务动作，按上表拆进对应 System，`hud.gd` 只留 UI 与命令转发。解决 A1（上帝类）。

### 4.2 数据模型（新增，替代部分 Dictionary）

```
Character（角色，原 current_character Dictionary 升级）
  ├─ 身份/爵位：social_level, noble_title, official_position
  ├─ 属性/技能：attr, skills, profession, profession_level
  ├─ 人生阶段：life_stage(幼年/少年/青年/中年/老年), age
  └─ 装备：equipped

Family（家族，原 family_data）
  ├─ 资产：wealth, granary(仓库), lands[](田地)
  ├─ 成员：family_tree, siblings, concubines, guests[](门客)
  └─ 传承：generation_count, family_policy, heirlooms

Faction（封国，新增——大周列国志双层模拟的"国家层"）
  ├─ 内政：population, tax_rate, buildings[](建筑)
  ├─ 军政：troops, generals[](委任人才), military_power
  └─ 外交：alliances[], tributes(纳贡)

Timeline（剧本时间轴，新增——无悔华夏剧本化）
  └─ events[]：按 year_range + 前置 + 一次性守卫 + 抉择分支
```

### 4.3 与现有代码/计划的衔接（不推翻，只重构 + 增量）

| 现有资产 | 去向 |
|---|---|
| `hud.gd` 里的业务动作 | 拆入各 System；`hud.gd` 瘦身为纯 UI + 命令转发 |
| `character_manager.gd` | 拆为 Character/Family 模型 + 各 System 的领域逻辑 |
| `game_state.gd` autoload | 保留为"只读全局状态 + 信号总线"，业务状态下沉到各 System/模型 |

> 本框架书只列"新增/变更的需求"，已有 8 大系统的详细规格仍以 `02_系统需求.md` 为准。每项标优先级：P0=架构地基（先做）/ P1=核心玩法增量 / P2=体验增强。

### 5.1 P0 —— 架构分层重构（一号工程，其他一切的前置）

| 需求 ID | 需求 | 说明 |

> 与现有 P1-P4 计划衔接：把"分层重构"作为 P0 前置插入，P1-P4 保持不变，P5/P6 为新增。

## 八、待确认事项（评审后定稿）

1. **P0 分层重构的时机**：是否同意"重构先行"（P0 插到 P1 之前/并行）？还是先按原 P1-P4 走完再重构？（我的建议：并行，P0 做地基、P1 做修复互不冲突）
2. **游戏定位**：mnrs 定位偏"重叙事的人生模拟"（古代人生式）还是"轻操作的历史策略"（无悔华夏式）？这决定 P2 的"放置推进"做不做、人生阶段线做多细。
3. **诸侯经营（P5）的深度**：做"轻经营"（几项委任+产出）还是"重经营"（对标大周列国志的完整内政外交军事）？（我建议先轻后重）
4. **人生阶段线（P6）的范围**：是否只做"少年读书 → 职业"这一小段（低风险、快见效），还是全 5 阶段一次铺开？
5. **政策/科技树**：中后期长期目标要不要本批次就上，还是先看 P5 诸侯经营的反馈再定？
