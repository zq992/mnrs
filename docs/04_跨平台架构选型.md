## 一、结论先行

1. **跨平台底座无需换引擎**：mnrs 用 Godot 4.3，本身就是跨平台引擎——一套代码导出 Windows / macOS / Linux / Android / iOS / Web。移动端 app、Windows、Mac 的"能跑"问题 Godot 已天然解决。
2. **真正要做的三件事**：
   - ① UI 适配：移动端触屏 vs 桌面键鼠、多分辨率、刘海屏安全区
   - ② UI 架构组织：面板栈 + AutoLoad 单例分离（顺带解决 hud.gd 上帝类）
   - ③ 国家经营地图系统：参考历史策略类开源项目的设计
3. **GitHub 参考分两类**：Godot 侧有成熟 UI 框架可**直接借鉴代码**；历史策略（大周列国志式地图）开源项目多为 Java/React/C++ 技术栈，作**地图系统设计参考**而非直接复用代码。

## 四、可借鉴的架构模式（mnrs 落地）

### 4.1 UI 面板栈控制流（解决 hud.gd 上帝类）

- 每个界面（主菜单 / 人生面板 / 国家地图 / 抉择弹窗 / 事件弹窗）做成独立 Panel 场景。
- 统一 `UIPanel` 基类：打开/关闭动画、输入隔离、缓存。
- 用管理器切换面板，而非在单个 `hud.gd` 里堆 5531 行。

### 4.2 AutoLoad 单例分离（对应 AR-3 系统化拆分）

| 单例 | 职责 |
|---|---|
| GameManager | 场景流/状态机 |
| DialogLauncher | 抉择/确认弹窗统一入口 |
| GamePersistence | 存档/读档 |
| ControlBlocker | 过渡期锁输入 |

### 4.3 跨平台输入适配

- 检测 `OS.get_name()` 切换输入方案：移动端触屏（`InputEventScreenTouch`/`ScreenDrag`），桌面键鼠。
- 按钮最小触控目标 44pt（iOS HIG）/48dp（Android Material），桌面可更小。
- 不依赖 hover（移动端无悬停），手指遮挡区（50-100px）避开关键信息。

### 4.4 分辨率与安全区

- 设计分辨率 + `Stretch Mode = canvas_items` + `Stretch Aspect = expand`。
- 移动端安全区：`DisplayServer.get_display_safe_area()` 或 SafeAreaX 插件。
- 横屏 1280×720（当前），竖屏可选 720×1280。

### 4.5 图形质量分级

- 桌面高质量（MSAA、SSAO 等后期），移动端轻量。
- 设置菜单提供分辨率/画质预设（低/中/高）。

## 六、定稿决策

| # | 决策项 | 定稿值 | 理由 |
|---|---|---|---|
| 1 | 移动端优先级 | 先桌面（Win/Mac）跑通，移动端（Android/iOS）后置 | 先验证玩法与手感，移动端适配后做 |
| 2 | 屏幕方向 | 横屏（沿用 1280×720） | 与现有 UI 布局一致，国家地图横屏更佳 |
| 3 | 地图形态 | 节点式州郡地图（三国大战略式） | 轻量、适合移动端、贴合"列国"离散领土 |
| 4 | UI 框架 | 按 godot-ui-template（GDScript）自建面板栈 | mnrs 是 GDScript 项目，避免引入 C# 依赖 |
