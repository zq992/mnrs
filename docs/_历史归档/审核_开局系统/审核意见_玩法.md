## 逐点审查

### 点 1：0 岁开局 → 0-16 成长 → 16 冠礼，节奏是否成立？

**结论：方向成立，但当前文档只给了一行定义（BR-7），是本次新增内容里定义最薄、空转风险最高的一段。按现状实现必然出问题。**

- 《古代人生》处理童年/少年期的正确姿势是：**出生 = 出身 roll（蒙太奇），少年期 = 几年私塾的轻量选择（读书/习武/玩乐三选一，属性即时+1~2），成年/科举才展开全部系统**。它的童年期每一年都有"输入 + 即时反馈"，且总时长压得很短。绝不让玩家空转等待。
- 本设计的 0-16 岁在年制下是 **16 个"年"**，其中 0-6 纯被动 7 年。按 TS-4「60 年 = 60 个操作周期（出生→老死）」的口径，0-16 占满 27% 的周期数；且每次新开局都从 0 岁重播。
- 但有一个缓解因素：0-16 只是**第一代**的开局引导（子女走"教养"系统，不重播 0 岁），所以它是"每次新局的 新手引导段"，不是整局 27% 的空转。也因此它**必须是全游戏设计最用心的首段体验**——玩家前 3 分钟决定留存。
- 风险点：0-6 被动 7 年若做成"每年点一下翻页"，就是教科书级空转；少年期若不设计成"选择 + 即时属性反馈"，就是 9 年重复的"读书/习武"二选一。

### 点 2：birth_year 随机 -1090~-1062 + 0 岁开局 → 伐纣时 16~44 岁，时间窗是否合理？

**结论：数学自洽（16~44 岁成立，且所有玩家都活过 -1046、都能赶上伐纣），但有两个玩法层面的硬问题：伐纣前的"剧本空洞" + 接入年龄方差过大。**

- 数学核对无误：成年年 = birth+16 ∈ [-1074, -1046]；伐纣年龄 = -1046−birth ∈ [16, 44]。✓
- **问题 A（空洞）**：BR-1 说剧本时间轴"起点 = 伐纣 -1046，历史事件沿此轴铺排"，但 BR-2/BR-3 让玩家从 -1090~-1062 出生。最老出生玩家要经历 **0-16 被动成长 + 28 年成年生活** 之后才等到第一个历史事件。也就是最坏情况玩家前 44 年人生全部落在"剧本轴外"的文王时期，BR-8「成年后经历历史事件」对这批人基本落空。
- **问题 B（方差）**：出生年均匀分布 28 年跨度 → 伐纣时年龄 16~44 岁。只有 -1062 出生（约 3.5% 玩家）恰好"16 冠礼 → 当年伐纣"；模态玩家约 30 岁接入。BR-8 强调的"正好赶上"其实是个尾部分布。如果你想要的是"少年以弱冠之身亲历鼎革"的统一 fantasy，这个窗口给不了；如果你接受"中年见证/少年亲历"两种体验，文档应该明说。

### 点 3：界面分工（国家委任 / 个人自行解决）是否清晰？与行动点模型是否冲突？

**结论：分工表的三行结构本身清晰（双池表达了"个人层叠加国家层"），但"委任"的机制语义完全没定义，且与 DL-1 的 6 点行动模型存在未协调的节奏冲突。**

- §2.5「君主委任/下政令，不事事亲为」+"委任+产出"（§11 #5 / R5）是**一次性配置 → 自动产出**的挂机式轻经营；DL-1「国家界面 6 点（国家）+4 点（个人）」+§2.3「行动类（每年行动点投入）」是**每年手动决策**。两者在同一处要求同时成立。
- 若委任=一次性人事任命，则 6 点/年无的放矢；若委任=每年重下政令，则诸侯一年 10 次决策（6国+4人），**操作量反超庶人的 8 点/年**，直接违背"不事事亲为"的身份 fantasy——成为君主的代价反而更累。
- "四支柱完整做、不能缺失"有歧义：若读成"玩家每年四支柱每项必做满"，则与 §5.2「每年点数有限，想做的事远超点数，玩家必须取舍」正面冲突，国家面就没了取舍只剩打卡。

### 点 4：出生季节彩蛋的必要性

**结论：纯叙事、不影响数值 → 价值低，可做可不做；但若要做，必须给钩子，否则玩家 3 秒后忘光。**

- BR-6 自己定了「季节仅叙事，不影响数值」——它就是一个 4 分支字符串表。作为"每次新开局的开场差异化"它能帮一点忙（与随机出生年叠加，让每次 intro 开场不同），但仅此而已。
- 真正的价值点在于游戏已有 **巫祝（祭祀占卜）职业** 与 卜筮玩法——出生季节 → 生辰 → 占卜批命 是一条自然的叙事链。不做成数值，也可以做成"开局批命一句 + 一条命运线注脚"（FL-1 的数据结构现成）。

### 点 5：幼年被动 + 少年读书习武，会不会与"每年行动点"打架（未成年减半）？

**结论：会打架，而且打赢的必然是"空转"。正解是未成年完全脱离行动点模型，而不是"减半"。**

- 若少年期硬套行动点：7-15 可用行动面收窄到只剩学习/社交，哪怕给 4 点/年（减半），有效选择也只有 1-2 个——正好踩中 DL-5「可用行动数 ≥ 点数」空转警告。
- DL-4 原文只减"耕作/修缮/出征"，**习武不在列**（这点是对的）；但"幼年减体力"措辞容易被实现者放大成"未成年整体减半"，一旦少年习武被归入体力类减半，就惩罚了少年期的核心玩法。
- 更本质的矛盾：0-16 岁**经济上不可自立**（不能耕作/履职），而行动点经济循环（02 §0.3 耗粮/俸禄/职业收入）全部假设"成年可劳作的户主"。未成年用行动点模型，机制上就不通。

## 三级清单

### P0（设计硬伤）

**P0-1：0-16 岁"操作面"整体未定义——成年系统不可用、少年系统没有，首段体验必空转**

- 【章节】02 序.2 BR-7 / BR-8；01 §3.1 TS-4
- 【原文】「0 ~ 16 岁成长阶段参考古代人生（幼年/少年养成）｜幼年（0-6）被动成长；少年（7-15）读书习武/少年事件，衔接 16 岁冠礼」「人生节奏：约 60 年 = 60 个操作周期（出生→老死）」
- 【问题】两文档对 0-16 岁只给了一句话。而行动点模型（DL-1~5）、经济循环（02 §0.3 每人 3 石/季耗粮）、职业履职（02 §1）**全部假设玩家是成年可劳作的户主**——幼年/少年既不能走行动点模型，又没有独立养成规则定义。0-6 纯被动 7 年 + 7-15 半交互 9 年，若按年制逐页翻，就是 16 个空转年；对每一次新开局重播，是留存最敏感的首段。少年期若用行动点减半，反而制造"未成年行动点打架"（见 P1-3）。
- 【建议】把 0-16 定为**三段式、每段机制明确**：
  1. **0-6 幼年 = 自动快进蒙太奇**（一段童年回忆文案 + 出生彩蛋 + 出身 roll），不占操作周期，30 秒内完成；
  2. **7-15 少年 = 独立轻量养成**（每岁 1 次"今年主修"选择：读书/习武/六艺/游玩 + 少年事件，属性即时 +1~2 可见），**不用行动点模型**，总时长压到 2~3 分钟——对齐古代人生"童年有选择、轻量、快节奏"；
  3. **16 冠礼 = 读少年养成结果**出职业/人生方向（衔接现有 `_on_profession_chosen`），并补一条"少年养成 → 成年初始属性/资产接续"的结算公式（幼年家庭背景如何变成 16 岁户主的财富/仓库/田地）。

### P1（高风险）

**P1-1：剧本起点（伐纣）与出生年（-1090~-1062）之间存在 16~44 年的"剧本空洞"，且历史接入年龄方差过大**

- 【章节】02 序.2 BR-1 / BR-2 / BR-8
- 【原文】「剧本时间轴起点 = 武王伐纣（-1046）｜历史事件（三监之乱→周公还政→…→犬戎灭周）沿此轴铺排」「玩家出生年份 birth_year 随机，范围约 -1090 ~ -1062」「武王伐纣（-1046）时玩家约 16~44 岁」
- 【问题】最老出生（-1090）玩家：0-16 少年 + 28 年成年，共 44 年人生落在伐纣之前——这 44 年完全处于"剧本轴外"，BR-8 承诺的"成年后经历历史事件"对这批人落空。同时 28 年出生跨度使玩家接入伐纣的年龄横跨 16~44 岁，只有约 3.5% 恰好"16 冠礼当年伐纣"，BR-8 强调的"正好赶上"在模态情况（约 30 岁）下严重弱化。
- 【建议】二选一（推荐 a）：
  - **(a) 收窄出生范围**至约 -1080~-1062：伐纣时 20~36 岁，语义锁定"文王末年出生、成年正当鼎革"，无老年接入、无 28 年成年空白，空洞缩到 14~20 年；
  - **(b) 保留范围但拥抱方差**：补铺伐纣前的文王时期轻量事件（演《周易》/招贤/伯邑考/渭水访贤等），并把"出生年 → 历史接入年龄"明示为特色（中年见证 vs 少年亲历是两种可复玩体验），而非只写"约 16~44 岁"一句带过。

**P1-2：国家界面"委任/产出"（轻经营挂机）与"6 点行动"（手动决策）两种节奏未协调，且诸侯操作量反超庶人**

- 【章节】01 §2.5；§5.1 DL-1；§11 决策 5；§十 R5
- 【原文】「君主委任/下政令，不事事亲为；内政/军政/外交/人才四支柱完整做、不能缺失」「国家界面 6 点（国家）+ 4 点（个人）双池」「先轻经营（委任+产出）」
- 【问题】委任若是"一次性配置自动产出"，每年 6 点无的放矢；若是"每年重下政令"，则诸侯 10 点/年 操作量反超庶人 8 点，违背"不事事亲为"的身份 fantasy。且"完整做、不能缺失"若被读成"每年四支柱必点满"，直接杀死 §5.2 的取舍感。
- 【建议】拍板一套语义：**"委任 = 基线自动产出（四支柱每年自动结算、缺人则产出减损），行动点 = 例外管理（调整支柱侧重 / 任命更换委任对象 / 危机事件临时插手）"**。"完整做"明确为"四支柱系统全部实现"，而非"玩家每年每项必做"。诸侯总操作量目标应 ≤ 庶人（如 4 国 + 4 人），让"制度治国、个人亲治家"从数值上成立。同时需补定义**委任对象池**（求贤来的贤才/家臣 → 谁在替你管司马/司徒），否则"委任"是空动词。

**P1-3：未成年行动点处理未定义，DL-4 措辞有被误读成"未成年减半"的风险**

- 【章节】01 §5.1 DL-4；02 序.2 BR-7
- 【原文】「幼年/老年只减体力类行动（耕作/修缮/出征）至减半，决策/关系类保持满点」「少年（7-15）读书习武/少年事件」
- 【问题】DL-4 的"幼年"与 BR-7 的"少年期"是两段，文档从未说明少年期是否走行动点、走几成。若少年期硬套行动点减半 → 4 点/年 + 可选行动面收窄 → 踩中 DL-5 空转警告；若少年习武被误归"体力类"减半 → 惩罚少年核心玩法。未成年与成年行动点模型在机制上根本不兼容（未成年不能谋生/履职，经济循环挂不上）。
- 【建议】明确一行硬规则：**"0-15 岁不参与行动点模型——0-6 自动快进、7-15 用少年养成（每岁 1 选），16 冠礼起才进入 8 点/年模型"**；并把 DL-4 的适用范围改为"成年后 + 老年"，明示少年习武满效，堵住误读。

### P2（建议）

**P2-1：出生季节彩蛋价值低，要做就给它钩子**

- 【章节】02 序.2 BR-6
- 【原文】「出生精确到'年' + 出生季节彩蛋（需做）｜季节仅叙事，不影响数值」
- 【问题】纯文本 4 分支，玩家 3 秒忘光，"需做"与收益不匹配。
- 【建议】钩到已有的巫祝/卜筮叙事链上：出生季节 → 生辰 → 开局"占卜批命"一句 + 写入命运线（FL-1 现成数据结构），不做数值。既保住"需做"的仪式感，又让彩蛋有记忆点。

**P2-2：少年养成必须"反哺"冠礼选择，否则冠礼是空选择**

- 【章节】02 序.2 BR-7 / BR-8；01 §6.1 CD-2
- 【原文】「16 岁冠礼成年，进入主要玩法」「选项级前置条件（属性/身份/资源/关系达标才可选）」
- 【问题】冠礼"选人生方向"若与少年养成无因果链，等于让一个 0 选择积累的婴儿直接空选方向，破坏 CD-2"资格由日常累积"的准则。
- 【建议】少年养成产出的技能/属性直接决定冠礼可选职业与初始职业等级（职业门槛、技能亲和已是现成表），让"7-15 读的书 → 16 能选什么路"成为可感知的因果链。

**P2-3：TS-4「60 周期」口径需随 0-16 压缩而重述**

- 【章节】01 §3.1 TS-4
- 【原文】「约 60 年 = 60 个操作周期（出生→老死）」
- 【问题】若 0-15 不占操作周期，实际是"约 44 成年操作周期 + 16 成长年"，口径自相矛盾，影响后续节奏设计的参照系。
- 【建议】改为「约 44 成年操作周期（16 冠礼→老死）+ 0-16 成长年（自动快进/轻养成）」。

**P2-4：最年轻出生（-1062）"冠礼当年即遇伐纣"是次优边界**

- 【章节】02 序.2 BR-8
- 【原文】「武王伐纣（-1046）时玩家约 16~44 岁」
- 【问题】-1062 出生者 16 岁冠礼当年就是伐纣，属性仅靠 9 年少年养成积累，大概率不满足从军/仕周的军功/声望门槛，第一个历史大事件反而"插不上手"。
- 【建议】接受它作为稀有边界（少年遇乱世、国难当头），但至少给 16 岁玩家一条低门槛参与线（如"以少年从军随征"事件选项，门槛降到战功 1），否则该边界玩家的历史初体验是看戏。

## 总结

**审查范围**：5 个重点点全部覆盖（0-16 节奏 / 伐纣时间窗 / 国家委任分工 / 出生季节彩蛋 / 未成年×行动点），单维度玩法与数值自洽。

**统计**：P0 × 1，P1 × 3，P2 × 4。

**最重要的 3 条意见**：

1. **（P0）0-16 岁是本次新增里最危险的一段**——它既接不进成年行动点/经济模型，又没有自己的机制定义。必须先定"0-6 自动快进蒙太奇 + 7-15 独立轻量养成（不用行动点）+ 16 冠礼读养成结果出职业"的三段式，否则首段体验必空转，留存直接受损。
2. **（P1）伐纣时间窗的叙事承诺和数值对不上**——所有玩家确实都赶上伐纣（数学没错），但最老出生者前 44 年人生完全落在"剧本轴外"（伐纣前无历史事件），且 16~44 岁的接入年龄方差让"正好赶上"只对 3.5% 玩家成立。建议收窄出生范围到 -1080~-1062，把"成年正当鼎革"变成确定性体验。
3. **（P1）"君主委任"与"行动点模型"是两种节奏，必须选一种讲法**——推荐"委任 = 基线自动产出 + 行动点 = 例外管理"，并补定义委任对象池；否则"不事事亲为"的 fantasy 会在实现时变成"诸侯每天 10 次决策、比庶人更累"的反讽。
